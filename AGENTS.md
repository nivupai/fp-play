# FP Play project conventions

## Scope and architecture

- Use **FP Play** as the public project name and `fp-play` as the npm package name and project-specific tool prefix. Preserve the original MIT copyright notice in `LICENSE`.
- Build incrementally. Milestone 13 adds logical datapath/GRS exploration, recorded signals/waveforms, and source-linked synthesis. Preserve all 473 Milestone 12 tests, immutable baseline RTL, and public numerical APIs. HLS, transformer hardware, and area/power optimization remain future work.
- Use React, strict TypeScript, Vite, Tailwind CSS, Vitest, ESLint, and Prettier. Prefer native platform APIs and keep dependencies minimal.
- Put reusable UI in `src/components/`, pure numerical code in `src/lib/numerics/`, and tests in `src/tests/`. Keep numerical models independent of React, the DOM, and display formatting.
- Favor small components, explicit types, deterministic pure functions, and documented module boundaries. Do not introduce routing or state libraries without a concrete need.

## Numerical correctness

- Test IEEE 754 behavior carefully. Never silently approximate edge cases. Disclose any approximation, unsupported case, or deviation in the API documentation and visible UI where relevant.
- For binary16 code, cover positive and negative zero, subnormals, normal boundaries, infinities, NaNs, underflow, overflow, and round-to-nearest, ties-to-even (including exact halfway cases and carry propagation). Test cancellation, GRS, carry, exact mathematical results, and per-operation exception indicators for arithmetic.
- Use independently derived expected bit patterns and public authoritative references. Exhaustively verify all 65,536 binary16 bit patterns where practical; do not validate an encoder only against its paired decoder.
- JavaScript `number` uses binary64. Do not assume it reproduces binary16 rounding or arithmetic. Preserve signed zero and explicitly specify NaN payload/canonicalization policy.
- Keep exact representation, rounding policy, and educational display formatting separate. The arithmetic model in `src/lib/numerics/fp16Arithmetic.ts` uses exact signed BigInt dyadics, lossless alignment, and one nearest-even rounding. Multiplication/FMA live in `fp16Multiply.ts`; all operations share `roundDyadicFP16.ts`. FMA must retain the exact product, without FP16 intermediate rounding, overflow, underflow, or flags. Nonfused comparison executes two real FP16 operations and unions their indicators. Its discriminated trace must come from the same computation as the result; never animate an independent approximate algorithm.
- All raw-pattern APIs validate uint16 inputs rather than silently masking. Preserve raw NaN metadata in `decodeFP16`; encoding a Number NaN canonicalizes to positive quiet NaN `0x7e00`.
- Adjacent-value APIs accept and return raw patterns. ULP means sign-independent binade spacing; see `src/lib/numerics/README.md` for zero, boundary, infinity, and NaN semantics.
- Arithmetic NaN policy: first signaling NaN, otherwise first quiet NaN in A/B order (A/B/C for FMA); quiet while retaining original sign and low nine payload bits. Subtraction must not flip a propagated NaN's raw sign. Opposing effective infinities and zero × infinity return `0x7e00` with invalid unless an input NaN is propagated. Zero × infinity raises invalid even with a quiet NaN C. Payload selection is implementation-specific, not a universal IEEE requirement.
- Tininess is detected after rounding to eleven-bit precision with unbounded exponent range; underflow requires both this tininess and final inexactness. Do not infer tininess only from the stored exponent: a result encoded `0x0400` can still raise underflow. See `src/lib/arithmetic/MULTIPLY_FMA.md` and keep explicit boundary regressions. Binary16 add/sub tiny results are exact on the `2**-24` grid, so do not invent underflow flags for exact subnormals. Overflow always sets inexact. Conversion flags and global sticky status are not modeled.
- Maintain independent lattice and directed references, exhaustive raw identities/cancellation and attainable midpoint checks, randomized differential tests, and trace reconstruction. Preserve all 338 Milestone 6 tests unchanged. Use the independent `2^-48` integer-lattice oracle for products/FMA, including precision-only tininess thresholds. Keep randomized tests and counterexample searches deterministic. CPU-heavy tests use per-test timeouts, not a global increase. Optional SoftFloat tools live in `scripts/`; do not vendor its source/binaries. State payload-policy differences and corpus limits. Do not claim full IEEE 754 conformance.

## Accessibility and interface

- Use semantic landmarks, ordered headings, accessible labels, keyboard navigation, visible focus states, and responsive layouts.
- Do not communicate a numerical field or state through color alone. Pair visualizations with text explanations and accessible alternatives.
- Clearly distinguish planned features from working functionality. Avoid controls that imply an unimplemented calculation works.
- Keep the raw uint16 pattern as the Explorer's source of truth. React components must consume the numerical library rather than duplicate decoding, rounding, adjacency, or ULP logic.
- Keep decimal text and the last converted binary64 input separate from the selected raw pattern. Raw edits/presets/neighbor selections clear conversion comparisons; invalid submissions retain the current pattern. Document Number parsing and special-value conventions.
- Display finite FP16 values with exact terminating decimal expansions, preserve visible `-0`, and retain NaN metadata during raw edits. Presentation helpers belong in `src/lib/explorer/`, separate from the numerical engine.
- Use native buttons with named bit positions and `aria-pressed`, labeled input validation, a single polite selection announcement, and color-independent field labels. Verify interactions with the actual engine; never substitute mock IEEE 754 decoding.
- Maintain light, dark, and system themes with readable contrast, responsive field layouts, focus indicators, and reduced-motion support. Theme choice is session-local.
- Keep microscope math in `src/lib/numerics/microscope.ts`, presentation/examples in `src/lib/microscope/`, and SVG components in `src/components/microscope/`. Use the existing conversion/adjacency/ULP engine as the source of truth.
- Generate viewport points by binary search over finite numerical ranks. Never render the complete FP16 lattice; cap rendered points, report omitted-point sampling, and keep sampled positions on actual representable values. A single geometric zero must not erase signed-zero input metadata.
- Rounding cells must handle exponent-boundary asymmetry, even/odd endpoint ownership, signed-zero half-cells, and the virtual ±65536 overflow neighbor. Do not label zero's sign seam as a halfway tie.
- Distinguish FP16 points, target, quantized output, and cell boundaries by shape/text as well as color. Supply keyboard/text alternatives to pointer interactions and exact tabular data. Disclose plot limits, rounded axis labels, binary64 decimal parsing, and error-computation precision.
- Arithmetic presentation/examples/docs belong in `src/lib/arithmetic/`; React controls and trace views belong in `src/components/arithmetic/`. Consume typed engine stages without duplicating arithmetic or GRS logic in React.
- Keep draft operand text separate from applied raw operands/results. Apply both operands and the operation atomically; invalid input retains the previous result. Decimal text is binary64-first then quantized to FP16. Preserve signaling NaNs through raw hex input; distinguish operand conversion from arithmetic rounding.
- The compatibility `exact.value` Number projection can round for wide FMA sums; coefficient/exponent is authoritative and must drive exact displays. Show exact dyadic results with terminating decimal formatting, rounded FP16 results, per-operation flags, and special-value short circuits. Stages are conceptual, not physical clock cycles or a particular hardware design. Keep fused, rounded product, and nonfused output encodings/flags distinct. FMA in the original FP16 workspace means FP16 output with one final rounding; distinguish it from the new mixed-precision lab’s FP32 accumulation. Provide native stage buttons and bounded Left/Right/Home/End controls, with horizontally scrollable long bit strings on mobile.
- Use native hash links for the four landing entries. `#fma` opens an existing verified preset; other workspaces retain their selections. Keep the FMA target present even before a comparison is applied, and support direct/repeated hash navigation without a router.
- Keep full binary strings intact and keyboard-scrollable; arrow keys on a long value must not trigger trace navigation. Controls need visible focus and comfortable targets. Verify theme tokens with `check:contrast`, but do not equate static token/DOM checks with rendered-browser or assistive-technology verification.

## Validation and workflow

- Use the Node version in `.nvmrc` and `npm ci` with the committed lockfile. Check package engine and peer requirements before upgrades.
- Run `npm run check` before committing: ESLint, Prettier, static theme contrast, full Vitest, TypeScript, and production build must pass. Then run `npm run check:release` on the built output. It must verify `/fp-play/` asset paths without deploying.
- Add meaningful regression tests for numerical behavior and interactive UI when introduced. Use independent reference cases rather than mirroring implementation logic.
- Keep README setup, scope, and roadmap current. Document limitations honestly.
- Production base is `/fp-play/`; navigation uses hashes, not server routes. Keep setup/preview URLs, metadata, and release checks synchronized. The Pages workflow must remain manual (`workflow_dispatch`) and main-only, with no push/tag/release triggers. Only its deploy job gets Pages/OIDC write permissions; do not auto-enable Pages or change repository settings. Pin official actions to release commit IDs.
- Keep README concise and full controls in `docs/USER_GUIDE.md`. Follow `docs/RELEASING.md` for explicit maintainer actions and record actual verification in `docs/RELEASE_VERIFICATION.md`. Never claim screenshots, browser checks, release publication, or deployment that did not occur.
- Use descriptive commits. Do not push, publish, deploy, or create a remote repository unless explicitly requested.
- Use only public standards and original or appropriately licensed open-source material. Never include proprietary hardware designs or internal Broadcom information.

## Multi-precision conventions

- Read [the mixed-precision contract](docs/MIXED_PRECISION.md). Fixed format descriptors and direct binary64 conversion live in `formats.ts`; BF16 must never convert through FP32. Preserve raw uint32 FP32 patterns as unsigned Numbers, raw NaN fields, signed zero, numerical adjacency, and binade ULP semantics.
- Keep the historical FP16 rounder and trace APIs intact. Generic arithmetic in `formatArithmetic.ts` uses exact BigInt dyadics and one destination rounding; mixed FMA never rounds or range-limits its product. Tininess after precision-only rounding must generalize with destination precision, not just inspect the encoded exponent. Test flags independently.
- `dotProduct.ts` defines only the five named modes A–E and 1–64 terms. B rounds FP16 products before FP32 accumulation; C retains exact products inside FP32 FMA. Sequential starts +0. Pairwise uses rounded product / FMA-with-zero leaves and rounded accumulator additions at tree nodes; document this different computation graph visibly. Exact one-leaf widening adds no rounding or flags.
- Track actual operands, term indices, results, rounding events, and flags in each computation step. Keep exact original binary64-dot and exact quantized-input-dot references separate. Never use Number product/summation to model these precisions or their exact references. Nonfinite exact references/errors are undefined; BigInt zero has no sign, so retain output sign in raw encodings.
- Mixed presentation/examples live in `src/lib/mixed/`; UI lives in `src/components/mixed/`. Invalid drafts preserve applied vectors/results. Long exact strings remain intact and scrollable. Label log-error plots as comparisons against each step's exact subsum, not a monotone prefix for pairwise evaluation. Native buttons/range/select and exact detail provide keyboard/text alternatives; jsdom range-change tests do not prove native browser arrow behavior.
- Preserve all historical tests unchanged. Use the separate `2^-2148` integer-distance reference, exhaustive BF16 classifications/midpoints, native FP32 conversions, deterministic independent arithmetic/reduction checks, directed specials/zero signs/overflow/tininess, and optional FP32 SoftFloat verification. Do not reduce coverage or exempt exception flags. Report actual corpus counts, payload-policy differences, and browser limitations. Run the full suite on Node 22.9 and 24 when available.

## Attention conventions

- Read [the attention contract](docs/ATTENTION_PRECISION.md). Numerical policies/events are in `attention.ts`; the exact-rational normalization helper is attention-specific. Reuse existing dot/BigInt arithmetic; never model FP16/FP32 arithmetic with unqualified Number operations.
- Accept only the five frozen named configurations and stable/naive methods. Bound Q to 4×8, K to 8×8, V to 8×4 with consistent dimensions. Reject sparse/ragged/non-Number matrices. Keep invalid drafts separate from applied Q/K/V. Allow explicit Number NaN/infinity for educational propagation; no raw NaN-payload entry is promised.
- Every input, dot, scale, softmax-input, shift, exp, denominator, quotient, probability, PV, and output boundary must come from the real computation log. Scale uses binary64 reciprocal Math.sqrt then quantization; exp uses binary64 Math.exp then quantization. Never claim correctly rounded format-specific sqrt/exp. Quotients use exact rationals and one RNE rounding, including precision-only tininess. Model conversions separately from host-exp diagnostics; exp exception flags themselves are not modeled.
- Stable softmax subtracts the rounded working-format maximum. Never silently repair NaNs/infinities, zero/nonfinite denominators, or all-zero probability failures. Do not renormalize stored probabilities. Document canonical quotient NaNs and explicit divide-by-zero diagnostics without changing existing four-flag APIs.
- Label stable modeled FP32, Number/binary64 baseline, and offline Decimal(100) reference distinctly. UI errors are binary64 estimates; relative error at zero and all nonfinite errors are undefined. Same-quantity comparison heatmaps share scales, retain signed numerical text, and supply raw encodings/native keyboard cell and step controls. Full traces are conceptual, never hardware timing/cost.
- Keep attention examples/parsing/presentation in `src/lib/attention/` and components in `src/components/attention/`. All twelve presets state phenomenon, expectation, and independent verification method. Keep `attention-vectors.json` test-only; do not bundle verification corpora or Python into the browser.
- Preserve all 390 historical tests unchanged. Validate quotient rounding independently, replay the 240 Fraction-generated pipelines in CI, run deterministic JSON export and optional Python/NumPy/Decimal verifier, and report actual counts/tolerances/NaN policies. Do not claim PyTorch, exp conformance, real-browser verification, or silicon measurements from numerical/DOM tests. Keep optional Python tools outside npm/runtime dependencies.

## RTL conventions

- Read [the RTL contract](rtl/README.md). Keep synthesizable SystemVerilog in `rtl/src/`, C++ simulation in `rtl/sim/`, fixed vectors/artifacts in `rtl/vectors/`, and verification scripts in `rtl/scripts/`. Tool dependencies are separate from frontend npm/runtime requirements. Never vendor proprietary designs or employer logic/documentation.
- Use a combinational fixed-width datapath with complete defaults, bounded constant loops, and no real-number, delay, clock, latch, or simulator floating-point shortcut. The 40-bit aligned / 41-bit exact 2^-24 lattice deliberately retains cancellation tails; GRS is generated after arithmetic. Observation ports are signals, not clocked stages or latency claims.
- Match the existing nearest-even, signed-zero, infinity, and first-signaling/otherwise-first-quiet A/B NaN policies strictly, including original B NaN sign on subtraction. Underflow stays clear because every tiny FP16 add/sub result is exact; do not invent an underflow flag or flush subnormals. Overflow implies inexact.
- Run `make -C rtl lint`, `make -C rtl test`, and `make -C rtl waveform` for RTL changes. Preserve the full 462,172-case fixed-seed corpus and all flag comparisons. Expected outputs come only from the existing TypeScript engine, not a duplicate RTL algorithm. Compare GRS/retained/increment/exact magnitude; compare raw NaN payload/sign strictly. Optional direct SoftFloat checks allow only its documented NaN metadata selection differences and never flag exemptions.
- Keep build products/VCD/failures under ignored `rtl/build/`. Save reproducible mismatches and bounded failing waveforms. Export `simulation.json` intentionally only after an actual complete simulator run; maintain source hashes. Normal tests must detect stale artifacts. Do not present software-computed values as RTL observations.
- The Arithmetic Explorer panel uses small precomputed records, explicit software-versus-recorded-RTL status, native controls, and full inspectable signals. It does not run Verilator or arbitrary RTL in the browser. Mark special-stage debug defaults as bypassed; distinguish fixed-grid coordinates from software's per-operation alignment coordinates.
- Preserve all historical numerical tests and APIs. Keep RTL CI separate and read-only; do not change the manual Pages deployment triggers/permissions. Report actual tool versions/counts, SoftFloat NaN policy differences, waveform generation versus GUI viewing, and synthesis/formal/browser limitations. Never claim area, power, timing, throughput, hardware latency, or device validation from a combinational simulation.

## Multiplication/FMA RTL conventions

- Follow [the width and exception contract](rtl/MULTIPLY_FMA.md). Retain the exact 22-bit product on a 2^-48 grid: 80-bit aligned product, 64-bit addend, 81-bit accumulation. True FMA rounds once; nonfused uses the rounded multiplier and original adder with flag union. Never import intermediate product flags into FMA.
- Keep the original add/sub source, corpus, tests, and artifact intact. New commands use `make -C rtl -f mul-fma.mk`. Verify at least 100,000 deterministic random triples plus full raw-pattern families, special cross products, independent boundary constants, and the separate lattice oracle. Compare every flag and strict FP Play NaN metadata; direct SoftFloat permits only documented NaN metadata differences.
- Serialize wide RTL observations as hexadecimal strings and compare with BigInt. Export artifacts only after complete actual simulation, with current source hashes. Keep finite-stage special-path defaults visibly bypassed. Browser inspection is recorded RTL versus explicitly computed software, never live hardware.
- Attempt generic synthesis with `make -C rtl -f mul-fma.mk synth`, check unsupported constructs/latches/loops, and report actual versions. Do not infer physical cost or timing. Preserve read-only RTL CI and manual-only deployment.

## Hardware analysis conventions

- Follow [the controlled synthesis contract](docs/HARDWARE_SYNTHESIS.md). Use functional-only wrappers in `rtl/analysis/units/`; prune debug outputs consistently. Nonfused must retain real intermediate rounding and exception union. Keep original `rtl/src/` sources and all historical tests unchanged.
- Analysis/variants belong in `rtl/analysis/` and `rtl/variants/`; pure netlist graph analysis in `src/lib/hardware/`, read-only UI in `src/components/hardware/`. Run `make -C rtl -f analysis.mk analysis` with the pinned suite. Reject stale verification certificates and mismatches before measuring.
- Every variant needs strict Verilator lint, full deterministic result/flag comparisons, and identical synthesis/library/IO assumptions. Keep combinational rounder equivalence distinct from whole-unit sampled verification and IEEE conformance. No numerical shortcuts are optimization tradeoffs.
- Download checksum-pinned public libraries/tools into ignored build output; preserve source/license identifiers. Keep raw scripts/netlists/reports/constraints and per-run manifests with commit, dirty state, timestamp, versions, settings, source/report hashes, verification results, and real measurements. Refresh browser artifacts only after actual successful analysis; reject stale hashes in ordinary tests.
- Cell area is not physical chip area or power; ideal-interconnect OpenSTA delay is not post-layout timing. Graph depth is not delay. Show unavailable values and stage attribution explicitly; do not fabricate metrics, path stages, or optimization wins. Keep expensive analysis manual and separate from frontend CI.

## Datapath explorer conventions

- Follow [the datapath contract](docs/HARDWARE_DATAPATH.md). Pure bounded record/VCD parsers, exact-engine comparisons and source linking live in `src/lib/datapath/`; components live in `src/components/datapath/`. Keep this workspace lazy and use the native `#datapath` anchor. No new numerical engine or browser HDL execution.
- Keep mathematical traces, logical functions, observed RTL, synthesized structures, and timing/area estimates distinct. Compare exact bits and every flag. Compare available finite observations using their actual grid scale. Mark missing fields and unknown bypass status; never reconstruct nonfused adder wires from software. Special-path defaults are bypassed, not executed finite rounding.
- GRS/retained/increment are observations; retained parity and carry are labeled derived annotations. Preserve true single-round FMA versus two real nonfused operations and flag union. Keep original example titles in provenance when display corrections are justified by observed parity.
- Preserve immutable RTL, historical tests and artifacts. The new offline `rtl/scripts/export-datapath-waveforms.mjs` requires full/directed verification certificates, validates actual VCD correlations, and hashes raw downloads/parser/exporter. Re-export the new waveform artifact after changing its parser/exporter. Normal tests must reject stale source files and malformed/corrupt observations. Keep raw download paths under Vite BASE_URL.
- Whole-unit metric comparisons require compatible core source hashes. Show exact recorded tools/library/constraints and unavailable data explicitly; never infer per-block area/delay, physical power or post-layout performance. VCD observation indices are not physical time or cycles. Native stage/GRS/wave controls and exact text tables complement SVGs; preserve long keyboard-scrollable bits.
- Browser/assistive-technology limitations and the reproducible manual checklist must remain explicit. Run all historical and new tests serially on supported Node versions; do not alter old assertions/timeouts to accommodate a larger DOM.
