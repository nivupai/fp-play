# R5: mapping a transformer layer onto a toy accelerator

Generated by `fp-play-runtime experiment --out results`. Every number below comes from that run.

## Setup

- Graph: one 8B-class transformer layer (hidden 4096, 32 query and 8 KV heads of dimension 128, FFN 14336) on one device, BF16 tensors: RMSNorm, Q/K/V projection, RoPE, K/V cache write, attention scores, softmax, attention × V, output projection, residual add, RMSNorm, gate/up projection, SiLU × up, down projection, residual add. Prefill is one sequence attending causally; decode is one new token per sequence with a 1024-token context read from the KV cache.
- Machine (illustrative, not a measured or named device): a 128 × 128 multiply–accumulate array, 256 vector lanes, 16 MiB SRAM, 1.5 TB/s HBM, one DMA engine and two chunk buffers. An activation stays in SRAM if it fits in half of it; weights and the KV cache come from HBM.
- Mapping: matrix products in output passes sized to a quarter of SRAM, column blocks of the array width and reduction chunks sized for double buffering; tiles entirely above the causal diagonal are skipped, partly masked tiles are computed in full. Vector ops cost illustrative per-element operation counts. Ops run strictly one after another, so each op's first load is exposed. A chunk's load and the previous chunk's compute overlap (two buffers).
- Results are in cycles. Two machine variants differ only in the assumed cycle time, which sets HBM bytes per cycle:
  - 1 ns cycle (illustrative): 1500 HBM bytes per cycle.
  - 4.179512 ns cycle (assumed: recorded FP16 FMA path delay): 6269 HBM bytes per cycle.
  The second takes FP Play's recorded combinational delay of its FP16 fused multiply–add (Nangate45, ideal interconnect, M12 artifact) as the cycle time. That is an assumption for illustration, not an achievable clock: it ignores pipelining, registers and layout.

## What this does and does not show

- It shows, for one explicit machine model and one simple mapping, where a transformer layer's cycles go in prefill and decode, and how far that mapping is from the roofline bound.
- The mapping puts tokens on the array's rows, so a decode step with fewer than 128 sequences leaves rows idle (padding). A mapping built for matrix–vector products (for example splitting the reduction across rows) is not modeled; decode's distance from its roofline bound is a property of this mapping.
- Every machine constant is illustrative. The mapping is one simple tiling with no operator fusion, no overlap between ops, no multi-device parallelism and one DMA engine; real compilers and accelerators do better and differ.
- SRAM bandwidth, bank conflicts, the NoC, power and area are not modeled. Vector-op costs are illustrative operation counts.
- The recorded FP16 FMA delay is used only as an assumed cycle time; it is a combinational path delay under stated IO constraints, not a clock frequency, and nothing here is a timing, area or power result.
