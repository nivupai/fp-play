# R3 rerun on the trained model: margins, flips and batch invariance

Generated by `fp-play-runtime experiment --out results`. Every number below comes from that run.

## Setup

- Models: R3's architecture with **random** BF16 weights (the `r3-decode` model, checksum `a77eb64e8be2d81b`) and with the **trained** weights of `r4-training` rounded once to BF16 (checksum `a1cf5b4453b7bcb9`). Everything else is R3's: binary32 local kernels, BF16 KV cache, the executed AllReduce under each wire policy, the R2 engine with every invariant checked after every step.
- Workload (both models): 32 copy prompts `BOS s1 … s24 SEP` of 26 tokens in 4 groups sharing their first 8 tokens, 24 greedy tokens each (the copy), block size 4.
- Grid: P ∈ {2, 4, 8} for every AllReduce schedule, plus the shard tree at P = 1, under both wire policies, against the P = 1 baseline of the same policy (logit scale 1 only: a positive scale cannot change greedy tokens). Batch invariance at P = 4 and the P = 1 control, as in R3.
- At-risk tokens, flips and perturbations are defined as in `r3-decode`: every generated token up to and including a prompt's first divergence; a flip is the token where it diverges; the perturbation is the largest |run − baseline| logit there, in ulps of the baseline's top logit. *Within reach*: margin ≤ 2 × perturbation (a flip implies it, by construction).

The prediction (only the ring's bits may depend on batch composition) is about bits, so it does not depend on the weights; the trained model tests it again on other values.

## What this does and does not show

- The same arithmetic, schedules and batch compositions run on both models. No prompt's logits match its baseline bit for bit in any grid run, for either model, so sharding still changes the trained model's logits. Within reach (margin ≤ 2 × perturbation, which every flip requires): 1784 of 27011 at-risk tokens with random weights, 0 of 29184 with trained weights.
- The trained model solves one synthetic copy task with confident predictions. This does not say how often a language model's tokens have small margins, so it is not a prediction for one.
- Batch composition changed the ring's logits in 2 of 2 ring rows with random weights and 2 of 2 with trained weights; it changed tokens in 52 and 0 (variant, prompt) cells.
