Generated by `fp-play-runtime experiment --out results` (fp-play-runtime 0.1.0). Re-running the command reproduces this file byte for byte.

**Setup.** `Y = X·W`, X 8×4096 and W 4096×512 in BF16 (seed `0xf991a7`); the hidden dimension is split across P devices. Each device accumulates its slice in FP32 (exact products, one rounding per term), converts the partial to the wire format, and the partials are AllReduced. 4096 output elements per run. All arithmetic is exact with one round-to-nearest-even per modeled operation.

## What this does and does not show

- Every algorithm performs the same number of wire-format roundings per element (P − 1) except exact-gather (one); the differences come only from association order, which each schedule fixes differently. Ring folds every chunk starting at a different rank.
- exact-gather is topology-independent: for fixed partials its result does not depend on the schedule, at the cost of all-gathering every input.
- Changing P changes the local partial sums themselves, so no AllReduce can make a sharded run match the unsharded kernel bit for bit.
- Inputs are synthetic (Irwin–Hall normal, weights scaled by 1/√hidden); the local kernel is one sequential order, not a blocked GEMM; the cost model ignores contention, compute and overlap. No hardware, interconnect or Etched-system measurement is claimed.
