# R1.1: a deterministic AllReduce over a fixed tree of shards

Generated by `fp-play-runtime experiment --out results` (fp-play-runtime 0.1.0). Re-running the command reproduces this file byte for byte.

**Setup.** The problem of [tp-allreduce.md](tp-allreduce.md) (`Y = X·W`, X 8×4096, W 4096×512, BF16 inputs, seed `0xf991a7`, 4096 output elements, BF16 output), but the hidden dimension is split into **S = 64 logical shards** that do not depend on the number of devices. Each shard's FP32 partial is the fused-chain kernel over its slice. One fixed binary tree over the shards combines them: at level k, node i absorbs node i + 2^k. P devices own contiguous blocks of shards. Each device's shards are reduced locally where the tree allows, cross-device nodes move the whole buffer, the root is on device 0, and a binomial broadcast follows.

**Invariant.** Every node of the tree is one accumulator-format addition, whether its children are on one device or two. That requires a reduce wire that carries every accumulator value exactly. `bf16` (BF16 shard partials, BF16 additions, BF16 wire) and `fp32-rs/bf16-ag` (FP32 additions and reduce wire, one rounding to BF16, BF16 broadcast) qualify. `bf16-wire/fp32-add` is rejected, because its BF16 messages would round a child only because it crossed devices.

## What this does and does not show

- P-invariance is a property of the fixed tree plus the invariant, checked here on this data for every P from 1 to S; `tests/shard_tree.rs` checks it on raw patterns (NaN, infinities, signed zeros) for several S, and `tests/vectors/tree-sums.txt` checks the tree sums against independent Python `Fraction` arithmetic.
- The bits are fixed for a given S, not across S: changing S changes the shard partials and the tree.
- Every device computes S/P shard partials separately instead of one partial over its slice, so the local kernel's summation order differs from the per-device kernel of the other schedules.
- With contiguous ownership every device sends and receives at most one message per tree level, so serialization never added a round here; the serializer is exercised on conflicting message sets in the tests.
- Whole buffers move at every cross-device node; a chunked, pipelined tree (which would trade rounds for bytes) is not modeled. Inputs are synthetic and the cost model ignores contention, compute and overlap. No hardware or interconnect measurement is claimed.
